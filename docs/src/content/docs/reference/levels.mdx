## Levels

| Level | Keeps | Removes |
| --- | --- | --- |
| `all` | everything | nothing |
| `value-add` (default) | anything that tells the reader something the code doesn't | `restates-code`, `commented-out-code`, `decorative`, `change-note`, `redundant-doc` |
| `necessary` | `explains-why`, `warning`, `api-doc`, `reference` | the above, plus `todo` and `clarifies` |
| `none` | tool directives and licences only | every other comment, without asking Jev |

Set the level in [`prolix.jsonc`](/reference/configuration/), with `--level` on the command line, or with the action's `level` input. The command line and the action input override the file.

## Categories

Jev scores each comment against every category. prolix adds up the scores of the categories the level removes and flags the comment when the total reaches the [threshold](/reference/configuration/) (0.6 by default).

| Category | Removed at | What it is | Example |
| --- | --- | --- | --- |
| `restates-code` | `value-add` | repeats what the code already says, or is filler addressed to a reader | `// increment the counter` |
| `commented-out-code` | `value-add` | disabled code left behind | `// const total = compute(items);` |
| `decorative` | `value-add` | banners, dividers and section labels | `// ===== Helpers =====` |
| `change-note` | `value-add` | narrates an edit instead of describing the code as it is | `// Updated to use the new API` |
| `redundant-doc` | `value-add` | docs that only repeat the name, signature or types | `/// Creates a new Config.` |
| `todo` | `necessary` | TODO, FIXME and HACK notes | `// TODO: handle pagination` |
| `clarifies` | `necessary` | summarises what non-obvious code does | `// Binary search over the sorted offsets` |
| `explains-why` | `none` | intent, trade-offs and business rules the code can't express | `// Retry once: the upstream drops the first request after idle` |
| `warning` | `none` | pitfalls, invariants and safety requirements | `// SAFETY: ptr is non-null and aligned` |
| `api-doc` | `none` | public behaviour beyond what the signature shows | `/// Panics if n is zero.` |
| `reference` | `none` | links to issues, specs or the source of copied code | `// See RFC 7231 section 6.5.1` |

### Config files

In YAML, TOML, HCL, JSONC, Dockerfiles, Makefiles and CMake, comments often label a section or keep a switched-off setting on hand. In those files `restates-code`, `decorative` and `commented-out-code` are kept until `necessary`.

## Directives

prolix never sends tool and compiler directives to Jev, and never removes them. It recognises them by their shape rather than by a list of tool names, so it also respects a linter it has never heard of:

- a switch word joined to a name or followed by a rule: `eslint-disable-next-line`, `react-doctor-disable-line`, `biome-ignore`, `# hadolint ignore=DL3008`, `/* c8 ignore next */`
- `no…` markers and `tool:setting` tokens: `# noqa: E501`, `// NOLINTNEXTLINE`, `# rubocop:disable`, `//go:build`, `// gitleaks:allow`
- tags and settings: `@ts-expect-error`, `$FlowFixMe`, `# shellcheck source=lib.sh`, `# syntax=docker/dockerfile:1`, `/* webpackChunkName: "x" */`
- version pins beside a hash, as in `uses: actions/checkout@<sha> # v4.1.1`
- shebangs, pragmas, regions, `/*!` licence headers, copyright and SPDX lines, `@generated` markers and `/// <reference>`

## Keeping a comment

Add `prolix-ignore` anywhere in a comment to keep it at every level:

```ts
// Pinned to 3.x until the upstream fix ships. prolix-ignore
```
