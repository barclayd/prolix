---
title: GitHub Action
description: Inputs, outputs and behaviour of barclayd/prolix, the GitHub Action that reviews the comments a pull request adds.
---

`barclayd/prolix@v0` runs prolix on the lines a pull request adds. When it flags something, it posts a summary comment and one-click suggestions for findings with validated fixes. Later runs update the same summary comment, which turns to ✅ once the pull request is clean. They reuse existing suggestions and resolve their review threads once the underlying finding no longer applies, preserving the discussion.

```yaml title=".github/workflows/prolix.yml"
name: prolix
on: pull_request
permissions:
  contents: read
  pull-requests: write
jobs:
  prolix:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.pull_request.head.sha }}
          fetch-depth: 0
      - uses: barclayd/prolix@v0
        with:
          api-key: ${{ secrets.TYPESAFE_API_KEY }}
```

## Inputs

| Input | Default | |
| --- | --- | --- |
| `api-key` | | Typesafe API key, from a secret. When it's empty or Jev rejects it, the pull request gets a comment that links to the repository's Actions secrets. Pull requests from forks and Dependabot don't get secrets, so for those the check is skipped with a notice. |
| `mode` | `prolix.jsonc`, then `standard` | `off`, `standard` or `strict`. See [Modes](/reference/modes/). `level` is the old name. |
| `scope` | `changed` | `changed` checks comments on the lines the pull request adds. `full` checks the whole repository. Events other than pull requests always check the whole repository. |
| `comment` | `true` | Post a summary comment when something is flagged, and keep it up to date. |
| `suggestions` | `true` | Post a review suggestion for each finding with a validated fix. Needs `scope: changed` and the checkout described below. |
| `fail-on-findings` | `false` | Fail the job when anything is flagged, instead of only advising. |
| `version` | `latest` | The `@prolix/cli` version to run, such as `0.1.0` or a canary version. |

## Outputs

| Output | |
| --- | --- |
| `flagged` | How many comments were flagged. |

The Markdown summary also goes to the run page.

## Checkout

`ref: ${{ github.event.pull_request.head.sha }}` and `fetch-depth: 0` check out the pull request's own commits rather than GitHub's merge commit, so suggestion line numbers match the pull request. Without them the action still posts the summary comment, and warns that it skipped the suggestions.

## Permissions

The job needs `pull-requests: write` to comment and suggest. Without it the action warns and carries on.

## Behaviour

- Exit code 2 from prolix, such as a bad config or Jev being unreachable, fails the step. Findings only fail it with `fail-on-findings: true`.
- A complete check of the current PR head resolves obsolete threads owned by the Actions bot. Human resolutions are respected. Unchanged source with a fluctuating model score, incomplete checks, and older runs leave existing threads open. Legacy suggestions are recognised using their original source range.
- Suggestions require a complete report from the current CLI, a score at or above `fixThreshold`, and a validated JS/TS/JSX/TSX edit. Findings without a safe fix still appear in the summary.
- Each run posts at most 50 new suggestions. The summary comment lists everything flagged.
- The summary comment is created only once something is flagged, so clean pull requests stay quiet.

## Examples

Block merging on findings, in strict mode:

```yaml
- uses: barclayd/prolix@v0
  with:
    api-key: ${{ secrets.TYPESAFE_API_KEY }}
    mode: strict
    fail-on-findings: true
```

Try a canary build from a pull request to prolix:

```yaml
- uses: barclayd/prolix@v0
  with:
    api-key: ${{ secrets.TYPESAFE_API_KEY }}
    version: 0.1.1-canary-abc1234
```
