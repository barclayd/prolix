When this is set up, prolix runs on every pull request. It checks only the lines the pull request adds, so it won't flag the comments already in the repo. It posts a summary comment and suggestions for findings with validated fixes, and updates the same comment on later pushes. To clear the comments already in a repo, see [Clean up an existing repo](/adopt/).

## Steps

<Steps>

1. **Add the workflow.** Create `.github/workflows/prolix.yml`:

   ```yaml title=".github/workflows/prolix.yml"
   name: prolix
   on: pull_request
   permissions:
     contents: read
     pull-requests: write
   jobs:
     prolix:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
           with:
             ref: ${{ github.event.pull_request.head.sha }}
             fetch-depth: 0
         - uses: barclayd/prolix@v0
           with:
             api-key: ${{ secrets.TYPESAFE_API_KEY }}
   ```

   Keep `ref` and `fetch-depth: 0`. They check out the pull request's own commits rather than GitHub's merge commit, which is how suggestions land on the right lines.

2. **Add `prolix.jsonc`** at the repository root:

   ```jsonc title="prolix.jsonc"
   {
     "mode": "strict",
     "ignore": ["src/types/env.d.ts"]
   }
   ```

   `"ignore"` takes globs for generated or vendored code that `.gitignore` doesn't cover, such as a generated `env.d.ts`, API clients or `vendor/`. Leave it out if there's none. See [Configuration](/reference/configuration/).

3. **In a JavaScript or TypeScript repo, add the CLI** as a dev dependency with the repo's package manager, so everyone runs the same version:

   | Package manager | Command |
   | --- | --- |
   | npm | `npm i -D @prolix/cli` |
   | pnpm | `pnpm add -D @prolix/cli` |
   | bun | `bun add -d @prolix/cli` |
   | yarn | `yarn add -D @prolix/cli` |

   Then add a script that checks what the branch adds:

   ```json title="package.json"
   "scripts": {
     "lint:comments": "prolix --changed=origin/main"
   }
   ```

   Use the repo's default branch in place of `main`. Other repos can skip this step and run `npx @prolix/cli`.

4. **Add the API key secret.** prolix asks [Jev](https://typesafe.ai) which comments to keep, so it needs a Typesafe API key from [typesafe.ai](https://typesafe.ai). Add it as a repository secret:

   ```sh
   gh secret set TYPESAFE_API_KEY
   ```

   `gh` prompts for the value, so the key never appears in your shell history. Without the secret, the pull request gets a comment that links to the repository's Actions secrets. Pull requests from forks and Dependabot don't get secrets, so for those the check is skipped with a notice.

   **Agents:** don't ask for the key or handle it yourself. Tell the user to run `gh secret set TYPESAFE_API_KEY`. If `gh secret list` already shows it, skip this step.

5. **Open a pull request** with these changes. Once the secret is set, the prolix check runs on it, and on every pull request after it.

</Steps>

## Check it works

If `TYPESAFE_API_KEY` is set in your shell, run prolix on what the branch adds:

```sh
npx @prolix/cli --changed=origin/main
```

It exits 0 when nothing is flagged and 1 when something is. To see it flag something, push a commit that adds `// increment the counter` above a line like `count++`. The pull request gets a comment and a suggestion that removes it.

## Options

- Make the check block merging with `fail-on-findings: true`. By default it only advises.
- Keep more comments with `"mode": "standard"`, which leaves TODOs and comments that only summarise what code does alone.
- Tune what's kept for your project with `keep` and `remove` categories, and a `behaviour` in plain English. See [Behaviour](/reference/modes/#behaviour).
- Check the whole repository rather than the lines each pull request adds with `scope: full`.

See the [GitHub Action reference](/reference/action/) for every input.

## Done when

- `.github/workflows/prolix.yml` matches step 1, including `pull-requests: write`, `ref` and `fetch-depth: 0`
- `prolix.jsonc` is at the repository root
- the `TYPESAFE_API_KEY` repository secret exists, or the user has been told to add it
- a pull request with these changes is open
