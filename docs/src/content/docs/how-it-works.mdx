---
title: How it works
description: How prolix finds comments, how Jev judges them, how the judgements are measured, and prolix's known limits.
---

1. **Find.** Parsers identify JS/TS/JSX/TSX comments. Other [supported languages](/reference/cli/#languages) use a byte-level lexer and produce review findings. YAML scalar contents are data, so embedded scripts inside them are not scanned.
2. **Skip directives.** Tool and compiler directives, licences and `prolix-ignore` comments are kept without asking Jev. See [Directives](/reference/modes/#directives).
3. **Judge.** Each remaining comment goes to [Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev) with a few lines of the code around it. Jev scores it against eleven [categories](/reference/modes/#categories), guided by any [behaviour](/reference/modes/#behaviour) in `prolix.jsonc`. Blocks larger than 2,000 bytes are kept without judgment and make the check incomplete. Identical questions are deduplicated. prolix sends up to 32 comments per request and up to 16 requests at a time, and retries rate limits and server errors with backoff.
4. **Decide.** A comment is flagged when the chance that it fits a category its mode removes reaches the threshold. `keep` and `remove` change which categories those are.
5. **Fix.** Eligible JS/TS/JSX/TSX findings must meet `fixThreshold` (default 0.9). The edit preserves token boundaries and significant line breaks; parsing and structural comparison must preserve executable syntax and literal content. Files are rechecked for concurrent changes before writing. Other findings remain for review.

## Evals

`tests/evals` in the repository measures Jev's judgements end to end. It runs the release binary against 15 fixtures in TypeScript, TSX, Rust, Python, Go, Java, C, Ruby, shell, SQL, CSS and YAML. Every comment in them is labelled with the categories a careful reviewer would accept. The fixtures cover every category, plus harder cases:

- warnings dressed as banners
- TODOs that also explain why
- prose that quotes code
- prompt-injection comments
- directives, which must never reach Jev

The report gives removal precision, which is the gate, because deleting a useful comment is the costly mistake. It also gives recall, the flip rate between repeated runs, a threshold sweep, per-category accuracy, top confusions and every wrong decision. `policy.json` pins a hash of the dataset and sets the floors, so changing a label or a floor is a reviewed change.

```sh
export TYPESAFE_API_KEY=...
cargo test --release --test evals -- --ignored --nocapture
```

## Known limits

- Automatic fixes are currently limited to parser-validated JS/TS/JSX/TSX; parsing does not prove that a documentation or tool directive is semantically redundant.
- YAML scalar contents are not scanned as embedded scripts.
- `{/* */}` comments in Svelte and Astro templates aren't linted.
- C++ raw strings (`R"(...)"`) aren't recognised.
- The cache only grows. Delete it to reset.

Found another? [Open an issue](https://github.com/barclayd/prolix/issues).

The checked-in eval corpus is a development set. `EVAL_DATASET_DIR` allows a separate, privately stored corpus with independently reviewed labels and repository-level holdouts. Reports record resolved model versions and a prompt hash. Draft field examples and the review process live in `tests/evals/README.md`.
